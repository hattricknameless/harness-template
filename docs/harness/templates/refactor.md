# 派工模板：重構

> 用途：不改行為、只改結構。
> 建議派法：subagent_type=`general-purpose`，model=`sonnet`；批次機械式改名可用 `haiku`。
> 前提：重構範圍必須先有行為驗證手段（測試或可實跑的檢查），沒有就先派實作模板補測試。

```
【目標與動機】
重構：＜改什麼結構，例如「把 X 從 A 檔抽到獨立模組」＞
因為：＜結構問題造成的實際痛點＞
行為不變的定義：＜哪些外部可見行為必須完全一致＞

【現況與素材】
- 涉及檔案：＜路徑列表＞
- 行為驗證手段：＜跑哪個測試／哪條指令可證明行為沒變＞

【驗收條件】
- 重構前先跑一次驗證手段並記錄結果（基準線）。
- 重構後同一驗證手段結果與基準線一致。
- 範圍鎖——不做：不改任何行為、不「順手」修 bug（發現 bug 記下來回報，不修）、
  不動 ＜明列＞。

【回報格式】
三段式，全文不超過 30 行：
1. 結構改動摘要（路徑:行號）。
2. 基準線 vs 重構後的驗證輸出結論。
3. 過程中發現但沒動的問題清單（給主對話決定要不要另開任務）。
- 用詞：只用日常常見的詞，不自創名詞或標籤；術語第一次出現用一句話解釋；
  同一概念全文用同一種說法（完整規則見 CLAUDE.md 溝通方式第 7 條）。
```
