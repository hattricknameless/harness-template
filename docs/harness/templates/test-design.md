# 派工模板：出題（pipeline S4a，設計驗收測試）

> 用途：在**實作動手之前**，依 spec 與該片的 What to build 設計驗收測試。
> 這是三角色分立的第一角：出題者**不得**是之後的實作者。
> 建議派法：subagent_type=`general-purpose`，model=`opus`（讀對需求、
> 想全邊界是高槓桿，故用 opus；認知難度僅次於閱卷，見 40-pipeline §0 排序）。
> **鐵則：fresh-context——只給下列素材，此刻沒有實作可讀、也不准去讀或猜實作。
> 你的測試要照 spec 出，不是照某個想像中的實作出。**

```
【目標與動機】
為以下 slice 設計驗收測試（出自 ＜docs/specs/<slug>/tasks.md＞ 的 T＜n＞）。
你是獨立出題者，不會參與實作。你出的題會成為實作的唯一驗收標準，
所以想不到的情況就等於沒人會測到——把這個功能會出錯的地方測到是你的核心價值。
但只測這個功能：不替既有功能補測、不寫重複的測試；測試越多，之後每次跑越慢。
＜貼入該片全文：What to build ／ 驗收 checklist ／ Out of scope＞

【素材】
- spec：docs/specs/＜slug＞/spec.md（User Stories 是驗收基準、Out of Scope 是範圍鎖）
- 測試邊界（seam）：＜spec 的 Testing Decisions；測試只准打在這裡＞
- 既有測試風格與工具：＜測試框架、命名慣例、放檔位置；沒有就說綠地＞
- 跑法：＜只跑這批新測試的指令＞
- ＜並行出題時才填：測試先寫在 ＜暫存路徑＞，不開測試環境；跑紅等輪到這片時再做，回報註明「尚未跑紅」＞

【做法規則】
- 先想清楚再出題：把這片會碰到的正常路徑、邊界、錯誤路徑、Out of scope
  的反例逐一列出來，挑出真的可能出錯的再變成測試。不要只測 happy path，
  也不要為了湊數把同一件事換個數字重測。
- 該片 What to build 若有「替未來功能預留」的項目，照它的驗收點出測試（例：多出來
  的欄位存得進讀得回、舊格式資料仍讀得到）；只測預留本身，不測未來功能。
- 單條測試要快：預估超過 1 秒的（例如整局數值模擬），先想能不能縮小範圍；
  縮不了就標成「慢測試」分類，並在測試開頭寫明為什麼慢。
- 測試只打核准的 seam：不測 private、不 mock 模組內部協作者。
  判斷法：實作全部重寫而行為不變時，你的測試不應該壞。
- 期望值來自獨立來源（spec 的例子、手算、已知字面量）。因為此刻沒有實作，
  你本來就無從抄實作的算法——維持這點，別自己臨時發明一套算法反推期望值。
- mock 只准打在系統邊界：外部 API、資料庫、時間、亂數。
- 測試打**正式呼叫路徑**——產線怎麼呼叫就怎麼測，內部函式最多當補充。測內部函式
  容易繞過正式入口才會觸發的行為，等於驗證自己的想像而不是真實世界。
- 涉及外部資源的斷言要驗「**還可用**」而不是「值變了」（檔案代號驗查得到型別、
  檔案驗實際寫入落點）。
- 用替身（mock）模擬外部行為前，先確認替身與被測對象走**同一條路徑**，並把這個理由
  寫進測試檔開頭；替身選錯路徑時整組測試是打在空氣上，照樣全綠。
- 測試換掉，不要疊上去：你的新測試如果已經完整涵蓋某條既有測試（同一個行為，而且你走的是
  同樣或更外層的正式入口），把那條舊測試列進回報第 4 點「建議刪除」，寫明被哪條新測試涵蓋。
  你自己不刪、不改它。
- 你出的這批測試此刻應該是紅的（因為還沒有實作）：只跑這批新測試、不跑全套，
  確認它們紅、且紅在「功能未實作」而不是「測試自己寫壞了」（import error、語法錯不算數）。

【驗收條件（出題工作本身的完成定義）】
- 該片 tasks.md 驗收 checklist 的每一條，都至少有一個對應測試。
- spec 中屬於這片的每條 User Story 的可觀察行為，都有測試涵蓋。
- 測試實跑過，全紅且紅得乾淨（附輸出結論）。並行出題、先寫在暫存區時例外：
  回報註明「尚未跑紅」，由指揮官在輪到這片時跑。試效果模式（見 41-pipeline-branches.md §2）定案後為最終行為出題時也例外：
  程式已經在了，測試可能直接綠，照實回報，由閱卷者逐條反證。
- 範圍鎖——不做：不寫任何實作程式、不碰 Out of scope、不改 spec/tasks/design。

【回報格式】
三段式，全文 ≤30 行：
1. 出了哪些題：測試檔路徑 ＋ 每條測試一句話（測什麼情況、對應哪條 checklist）。
2. 驗證：實跑輸出結論，確認全紅且紅在「未實作」。
3. 我覆蓋了哪些邊界／我判斷這片還有哪些情況我沒出題（誠實列出缺口，
   供之後的獨立閱卷者接手）。
4. 建議刪除的舊測試（沒有就寫「無」）：每條一行「舊測試全名｜被哪條新測試涵蓋｜為什麼是同一件事」。
- 用詞：只用日常常見的詞，不自創名詞或標籤；術語第一次出現用一句話解釋；
  同一概念全文用同一種說法（完整規則見 CLAUDE.md 溝通方式第 4 條）。
```
