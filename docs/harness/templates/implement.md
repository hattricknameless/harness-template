# 派工模板：實作

> 用途：新功能、新檔案、修 bug。
> 建議派法：subagent_type=`general-purpose`，model=`sonnet`（一般）／`opus`（跨檔或約束多）。

```
【目標與動機】
實作：＜要什麼行為，用輸入→輸出描述，不要只寫功能名＞
因為：＜這是給誰用的、解決什麼問題——邊界情況照這個動機判斷＞

【現況與素材】
- 相關檔案：＜路徑列表；不知道就先派搜尋模板查清楚再派這份＞
- 既有慣例：＜要遵循的模式，或寫「參考 ＜某檔＞ 的寫法」＞

【驗收條件】
- ＜可客觀檢查的條件 1，例如：跑 `pytest tests/test_x.py` 全綠＞
- ＜條件 2，例如：輸入 X 時輸出 Y；輸入非法值時拋 ValueError＞
- 附帶至少一個涵蓋主路徑的測試。
- 範圍鎖——不做：＜明列不准動的東西，例如「不改既有 API 簽名」「不升級依賴」＞

【回報格式】
三段式，全文不超過 30 行：
1. 做了什麼：改動的檔案列表（路徑:行號）+ 每個一句話。
2. 驗證結果：實際跑了什麼指令、輸出結論（失敗就貼失敗原文）。
3. 沒做什麼／假設了什麼／卡在哪。
- 用詞：只用日常常見的詞，不自創名詞或標籤；術語第一次出現用一句話解釋；
  同一概念全文用同一種說法（完整規則見 CLAUDE.md 溝通方式第 7 條）。
```
