# Wrap：收工程序

依序執行，每步有完成判準：

1. **更新 `docs/STATUS.md`**（整檔覆寫，只保留現況，歷史一律去 DEVLOG）：
   目前目標一句／進行中（指向 `docs/specs/` 未完成項）／下一步 ≤3 條／
   卡點與待決事項。
   完成判準：一個零前後文的新 session 只讀這檔就知道從哪接手。
2. **追加 `docs/DEVLOG.md`**（最新在上，一個 session 一則，每則 ≤4 行）：
   `## YYYY-MM-DD` ＋ 做了什麼一句 ＋ 關鍵決定或發現一句（已有 ADR／教訓
   就只給路徑，不重複內容）＋ 未完事項一句。
   本次有出貨 → 「做了什麼」首句用 `vX.Y.Z: <desc>` 開頭，且與 commit
   標題同字串；編號規則見 `docs/harness/50-versioning.md`。
   `$ARGUMENTS` 有內容就當作補充備註寫進這一則。
3. 本次有踩坑 → 照 `docs/harness/30-maintenance.md` §3 的三行格式寫教訓
   到對應制度檔（沒踩坑就跳過，不要硬寫）。
4. 本次得知的**耐久**事實（使用者偏好、專案方向改變）→ 更新記憶目錄；
   只在本次對話有意義的不存。
5. 回報：動了哪些檔（路徑）＋ 給下一個 session 的一句建議開場。

## 硬規則

- DEVLOG 只追加，不改舊條目；STATUS 不留歷史。
- 兩檔都不重複 git／ADR／教訓已記錄的內容——只給指標（路徑）。
- 條目超過 4 行就砍到 4 行；寫不進 4 行代表該落檔的東西沒落檔，先落檔再寫指標。
